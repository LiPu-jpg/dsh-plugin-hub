**v1.6.11 — Sharper install-failure attribution: missing dependencies point to the author, blocked builds are no longer "unclassified"**

DSH Plugin Hub is the community plugin marketplace for DeepSeek Harness (website https://dsh-plugin.org). This release sharpens who the hub blames when an install fails.

**What's new**

- When a package a plugin depends on does not exist on the public npm registry, the failure now names that plugin dependency as the cause and offers a direct link to report it to the plugin repository.

- If the package does exist on the official registry but the registry configured on your machine has not synced it yet, the hint points you at the official registry instead — still not a plugin problem.

- A failed install whose log carries only the host build-allowlist summary (the raw pnpm error goes to the diagnostics log file) is now recognised as a build script blocked by the pnpm allowlist, with an actionable hint, instead of falling back to "cause unclassified".

- Package names shown in failure details are no longer URL-encoded: scoped names such as `@scope/name` are displayed as-is.

Thanks to @China-wdz for the report.

**Install**

```bash
dsh plugin --profile web add dsh-plugin
dsh plugin --profile web add git+https://github.com/dshplugin/dsh-plugin-hub.git
```
